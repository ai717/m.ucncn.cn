🔍 市场痛点剖析与商机本质

【真实市场痛点与供需断层】想出电子书的人卡在最磨人的环节：选题调研、大纲、正文、排版、导出，每一步都要换工具、耗时间；很多营销人与小生意主明明有料可写，却因为'写一本书太费劲'一直没动手。市面上的 AI 写作工具只给零散段落，不给一本能直接卖的成品。
【破局机制与商业套利切口】把'一句话想法变成一本能卖的电子书'做成一条龙：调研、大纲、写作、排版、导出全包，用户只管给想法；技术门槛被 Vibe coding 打下来，非技术创始人用 Lovable + Claude Code 就能做出 MVP；真正的壁垒不在代码，在营销：创始人靠营销老本行，大量测试 Meta 广告创意、优化漏斗、叠加额度包与教程加购抬客单，4 个月做到 13 万美元收入。卖的是'省掉的几十小时重复劳动'，不是技术本身。

🛠️ 4 阶段落地实施 SOP

阶段 01 · 锁定一个会掏钱的写书人群：营销人与小生意主 逆向洞察

访谈 10 个想出电子书引流/卖货的人：他们现在怎么出书、花了多久、愿付多少钱；确认客群是'有料可写、缺时间'的营销人与小生意主，不是学生与纯好奇者；把竞品（通用 AI 写作工具）的差评扒一遍，确认'只给段落、不给成品'是最大缺口。

🏁 阶段交付物:10 份访谈纪要 + 竞品差评清单 + 锁定的首发客群
阶段 02 · Vibe coding 两周出 MVP：调研→大纲→成书→导出 极速构建

用 Lovable/Claude Code 搭 MVP：输入想法→自动调研→生成大纲（可改）→逐章写正文→排版导出 PDF/EPUB；先做一种书型（实操指南类）做到能用，不贪多；本包 ebook_builder.py 可直接跑通大纲生成与样章导出；从第一天起写测试，别等代码乱到看不懂才重构。

🏁 阶段交付物:可跑通的 MVP + ebook_builder.py 脚手架实测通过 + 一种书型端到端跑通
阶段 03 · 订阅打底 + 额度包与教程加购抬客单 商业闭环

订阅 29 美元/月起，叠加按量额度包（多写多付）与教程等数字产品加购，把单个客户价值做厚；Stripe 接入订阅与一次性加购；每本书生成后引导用户晒成果，换口碑与复购；每周算一次真实获客成本与毛利，广告费占比一旦超过 60% 立刻收紧。

🏁 阶段交付物:支付闭环跑通 + 加购漏斗上线 + 每周毛利看板
阶段 04 · Meta 广告小步快测：每天测创意，亏得起才放大 渠道冷启

先拿 500 美元测 10 条广告创意，只放大获客成本低于客单价 1/3 的那条；漏斗每一步（点击→注册→试用→付费）都埋转化数据，堵漏再放量；广告素材每周换一批，防创意疲劳；同时在 YouTube/社群沉淀免费电子书样章，拿自然流量对冲广告依赖。

🏁 阶段交付物:跑通 1 条正向 ROI 广告 + 漏斗转化看板 + 每周创意更新节奏

⚠️ 避坑警戒与防范底线

全部收入数字（4 个月超 13 万美元、1,700 多付费客户、约 5,000 注册）均为创始人自述，未见 TrustMRR/Stripe 直连核验，引用时必须写清'创始人自述'，不得当审计数用；每月 2~3 万美元广告费是双刃剑，广告账户一旦被封或创意疲劳，增长立刻断档，须留自然流量后手；AI Wrapper 门槛极低，同类产品几天就能抄一个，护城河只在漏斗与广告素材的持续迭代，不在代码；Vibe coding 一时爽，代码乱到看不懂就要重构，MVP 阶段就要留测试与文档；AI 生成的书内容同质化风险高，须提醒用户人工审校，否则差评会反噬口碑。
